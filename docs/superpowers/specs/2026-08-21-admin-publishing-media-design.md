# SinoHerb 后台上架与全站图片管理设计

## 目标

让运营后台同时管理产品上下架和全站展示图片。产品状态切换不改变产品数据；图片替换不需要修改 HTML 文件，并且在未配置新图片时保留现有默认视觉。

## 方案

采用“固定图片位 + 后台上传”的方式。每个图片位有稳定的 key，前台按 key 读取当前图片，后台按页面分组展示和替换图片。首期图片保存在应用服务器的持久化上传目录中，Nginx 以只读方式提供访问。

### 图片位分组

- 首页：主视觉、推荐产品、体质检测入口、FAQ/理念引导等
- 产品页：产品列表视觉、推荐区域视觉
- 产品详情页：每个产品的主图、详情图和使用场景图
- 理念页：主视觉、理念卡片、日常场景图
- 体质检测页：聊天区域和结果区域的引导视觉
- 关于页：品牌主视觉和服务说明视觉

每个位点包含稳定 key、页面分组、展示名称、默认资源路径、当前资源路径和替代文本。产品图片位使用产品 slug 关联，不把文件名直接写入页面模板。

## 数据与文件

新增 `media_assets` 表：

- `id`、`slot_key`（唯一）、`page_group`、`label`
- `file_path`、`mime_type`、`file_size`
- `alt_text`、`status`、`created_at`、`updated_at`

上传文件使用随机安全文件名，限制为 JPG、PNG、WebP、SVG，单文件大小上限 5 MB。新文件写入 `uploads/media/`，旧文件进入同一目录的版本备份，不在替换时直接删除。Compose 为 API 和 Nginx 挂载同一个持久化上传卷；Nginx 只读挂载该目录。

## API

公开接口：

- `GET /api/v1/media`：只返回已启用图片位的当前 URL 和替代文本

管理员接口：

- `GET /api/v1/admin/media`：按页面分组返回全部图片位和当前状态
- `POST /api/v1/admin/media/:slotKey`：上传并替换图片，支持 multipart 文件和替代文本
- `PATCH /api/v1/admin/media/:slotKey`：更新替代文本或启用状态
- `POST /api/v1/admin/media/:slotKey/restore`：恢复该图片位最近一次备份

所有管理员接口继续使用现有管理员会话鉴权。上传接口在写入数据库前校验 MIME、扩展名、大小和图片位是否存在；失败时不修改当前图片。

## 后台界面

后台分为“订单”“产品与库存”“全站图片”“模型状态”四个区域：

- 产品区增加状态筛选：全部、已上架、已下架
- 每行显示中文状态，并根据当前状态显示“下架”或“上架”
- 切换状态后保留筛选条件并刷新列表
- 图片区按页面分组显示图片位、预览、文件名、更新时间和替代文本
- 每个位点提供“替换图片”“恢复上一版”和“保存替代文本”操作
- 上传中显示进度，成功后立即刷新预览；失败时保留原图并显示原因

## 前台接入

前台初始化时请求公开媒体接口，将返回的 slot key 映射到对应图片元素；接口不可用或图片位没有自定义资源时，继续使用现有静态资源。产品列表和详情页使用产品 slug 生成图片位 key，避免新增产品时修改页面模板。

## 安全与运维

- 只允许已登录管理员上传和替换图片
- 统一生成文件名，拒绝路径穿越和可执行扩展名
- 上传目录不允许 API 以外的服务写入
- Nginx 对上传文件只提供静态读取，不执行脚本
- 旧版本保留最近 10 个，超过后按时间清理
- 数据库备份包含图片位元数据；上传卷由部署脚本单独备份

## 验证

- API 测试图片位列表、未登录拒绝、类型/大小校验、替换和恢复
- 产品状态测试上架→下架→上架的完整循环
- 浏览器验证后台筛选、按钮状态、图片预览和替换后刷新
- 浏览器验证首页、产品页、详情页、理念页等图片位都能读取默认或自定义资源
- Docker Compose 验证 API 与 Nginx 共享上传卷，重启后图片仍可访问
